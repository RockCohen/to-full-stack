# 答辩 · TS 类型系统 10 问

> 用法:整个文件发给 AI,让它逐题问你、逐题追问,直到你能独立讲清。
> 通过线:**≥8 题**。答错的 → `tutor/misconceptions.md` + 针对性小实验修补。
> 规则:口头作答(打字也行),不许翻 MAP.md 和实验卡——卡住了就答"不知道",这比编的强。

1. TS 的 `interface` 和 Java 的 `interface` 最本质的一个区别是什么?用"血统/体检报告"之外你自己的话说一遍。
2. 对象字面量直接赋值会触发"多余属性检查",绕道变量就不会——这是 TS 的 bug 吗?这个设计在防什么?
3. 联合类型 + 收窄,对应 Java 里哪套组合拳?为什么说 TS 把它做成了"日用品"?
4. `never` 怎么当"编译器证明器"用?描述一次它帮你拦住事故的完整过程。
5. `unknown`、`any`、`never` 三者各是什么?分别对应 Java 里的什么(或什么都没有)?
6. Java 泛型和 TS 泛型都"擦除",差在哪?各举一个你能观察到的证据。
7. TS 的 `interface` 在运行时不存在,那接口数据的字段靠什么保证?这个分工和 Spring 里哪个环节对应?
8. `readonly` 和 Java `final` 像在哪、哪里根本不是一回事?
9. 为什么很多 TS 团队禁用 `enum`?替代方案是什么,顺便白拿什么能力?
10. **综合题**:给你一个后端接口返回的 JSON,你要在 TS 里建模。说说你的完整策略——类型写在哪一层,运行时校验放哪一层,为什么这个顺序不能反。
