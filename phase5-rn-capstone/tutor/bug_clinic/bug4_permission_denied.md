# 🚑 门诊 4 号(读档)· 症状:用户拒绝定位授权后,App 直接崩在启动页

> 形式:读档诊断。病例是"第一版外卖骑手打卡功能"的伪代码——先写诊断假设,再给修复设计。

## 现场档案

```tsx
// App 启动流程(伪代码)
function App() {
  useEffect(() => {
    const pos = Location.getCurrentPositionAsync();   // 步骤 1:直接取定位
    startTracking(pos);                                // 步骤 2:开始上报
  }, []);
  // …
}
```

## 上线后的事故报告

- Android 首次启动:系统权限弹窗 → 用户点"拒绝" → **App 崩溃**(未处理异常)
- iOS 用户此前在系统设置里选了"永不允许":**启动即崩,连首页都进不去**
- 测试同学没拒绝过权限,所以测不出来

## 诊断提示

- 步骤 1 在"权限未授予"的世界里会返回什么?抛什么?这段代码假定了几种世界状态?
- "拒绝"是一次性事件还是一种**持续状态**?"永久拒绝"(系统设置里关掉)和"本次拒绝"的处理为什么必须分开?
- 你后端调第三方接口时,"对方未授权/欠费"是怎么处理的?这里是同一个问题,只是"对方"是用户。

## 任务

1. 画出权限的三态路径图:未决定 → 授予 / 本次拒绝 / 永久拒绝,每态的 UI 与下一步。
2. 给出修复后的启动流程伪代码(要求:拒绝态下 App 可用,功能优雅降级)。
3. 追问:为什么上架审核(iOS 尤其)会卡"拒绝权限后崩溃"?审核员站在谁的视角?
