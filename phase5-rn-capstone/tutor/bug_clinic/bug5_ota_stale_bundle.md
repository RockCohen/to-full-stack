# 🚑 门诊 5 号(读档)· 症状:OTA 推了新版本,客服收到的截图还是旧界面

> 形式:读档诊断。先写诊断假设,再给发布策略修复。

## 现场档案

你的 RN App 用 OTA(Expo Updates / CodePush)热更 JS bundle:

```text
周一 10:00  发布 v1.4.0(原生发版,应用商店)
周三 15:00  发现 v1.4.0 的订单页有个 UI bug
周三 15:10  用 OTA 推了修复 bundle(立即全量)
周四 11:00  客服仍收到 3 张"旧界面"截图,用户坚称重启过 App
```

## 诊断提示

- OTA 更新包**什么时候**生效?下载完成后立即?还是**下次冷启动**?
- 三位用户分别对应哪种可能:① 从未重新启动;② 下载失败回滚到旧包;③ **没用 OTA 渠道**(直接从商店装的旧原生版,OTA 只能更 JS,更不了原生);
- 你后端的"配置中心热下发"有没有同款问题?(客户端多久拉一次、拉到后何时生效、拉不到怎么办)

## 任务

1. 解释 OTA 的生效模型(下载/安装/激活三个时机),并指出"立即全量"错在哪。
2. 设计一个修复发布策略:灰度(1% → 10% → 100%)、强制回滚开关、以及**如何回答客服"用户到底是不是新版"**(版本上报)。
3. 追问:哪些变更 OTA 天然做不了?列出三类,并说明为什么"发布节奏由最慢的一端决定"。
