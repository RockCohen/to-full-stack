# 螺旋地图 · 四条不变量的概念脊柱(教师侧规划)

> 借鉴 OpenMAIC「spiral-curriculum」技能包。它与本仓库"不变量表主旋律"同构,但多了一套严格的检验:
> **Revisit 不等于 Review**——同一概念每次回来,必须能回答"这次比上次多了什么",否则就是重复,不是螺旋。
>
> 两层分工(对齐原设计):
> - **本文件 = 教师侧规划**:概念脊柱、遭遇史、六阶段螺旋契约、假螺旋自检。AI 助教参考,平时不用读。
> - **不变量表.md = 学生侧账本**:每场打卡一格,只需写概念 + 一句"这次多了什么"。

## 升阶操作符(打卡时用括号缩写标注)

| 操作符 | 缩写 | 含义 |
|---|---|---|
| ADD_COMPLEXITY | 复杂 | 增加变量或相互作用 |
| ADD_RELATION | 关系 | 与另一个概念形成必要关系 |
| ABSTRACT | 抽象 | 从案例上升到一般模型 |
| FORMALIZE | 形式 | 引入符号、模型或专业语言 |
| CHANGE_REPRESENTATION | 表征 | 操作/图像/符号表征之间重构 |
| INCREASE_TRANSFER_DISTANCE | 迁移 | 进入更陌生或跨领域的情境 |
| ADD_EXCEPTION | 反例 | 加入反例、边界、局限 |

一次重访通常 1 个主操作符 + 少量辅助,不要一次叠满。

## 概念脊柱(初始理解目标 → 最终理解目标)

每条不变量写成一句**可迁移的理解**,不是名词:

| 不变量 | 初始理解目标(进阶段 0/1 时) | 最终理解目标(毕业时) |
|---|---|---|
| **数据放在哪** | 变量不是都在栈上——被捕获就逃逸到堆 | 能对任意语言/运行时画出"谁住在哪、谁管生死"(JVM 堆 → JS 堆 → Fiber 槽位,同一套可达性分析) |
| **谁说了算** | 单线程也能并发——靠队列不靠线程 | 能在任意"执行模型"(OS 线程池/事件循环/框架调度器/原生桥)里指出仲裁者与队列 |
| **怎么不打架** | 共享内存要同步,消息订阅是一种替代 | 能按场景选武器:锁/CAS → 不可变更新/单向数据流/缓存失效,并说清为什么换 |
| **数据怎么流动** | 异步读的凭证化:Future/Promise 一家 | 能端到端讲清一次数据读写穿过 缓存→网络→浏览器缓存→框架缓存→渲染 的完整管线 |

## 六阶段螺旋契约

每阶段七字段;`future_hook` 是故意留下的 productive incompleteness——先建立可用但不完整的模型,后续重访再重组。

**phase0 · TS 与异步**
- returning:无(脊柱起点)
- new:结构化类型/收窄、泛型擦除、事件循环、Promise 状态机
- added_complexity:—
- new_relation:类型 ↔ 体检报告;Promise ↔ 无 get() 的 Future
- representation_shift:从运行时值到"类型即证明"
- transfer_target:CompletableFuture、Reactor EventLoop
- future_hook:事件循环只讲单线程,多进程留 S9;回调队列的堆行为留 S11

**phase1 · 运行时与内存**
- returning:事件循环(升阶到微内核)、Promise(在异步回调里诞生闭包)
- new:闭包、this/原型、GC、响应式 store
- added_complexity:数据开始"搬家"——栈帧 vs 堆,寿命跟着引用走
- new_relation:闭包 ↔ GC 可达性;订阅 ↔ 观察者模式实做
- representation_shift:代码 → 内存图(ReachSim/ClosureSim)
- transfer_target:jmap/jstat、微内核 OS
- future_hook:20 行响应式 store 就是 React 状态库共同祖先,S16 起反复回用

**phase2 · React**
- returning:堆与槽位(hooks)、事件循环(渲染调度)、订阅(store → 状态管理)
- new:JSX、vdom/diff、hooks 家族、单向数据流
- added_complexity:UI = f(state) 三层机制(描述 → 协调 → 提交)
- new_relation:Fiber 槽位 ↔ 闭包堆逃逸;diff ↔ 脏页最小回写
- representation_shift:任务队列 → 新旧树对照(DiffSim)
- transfer_target:OS 调度器、COW
- future_hook:数据获取刻意留白(fetch 归阶段 3);Context/Zustand 只讲思想

**phase3 · 数据与网络**
- returning:缓存(后端老本能)→ Query;Promise → fetch
- new:fetch 语义、CORS、Cookie/JWT 存放、TanStack Query
- added_complexity:分布式缓存语义整个搬进浏览器
- new_relation:queryKey ↔ 缓存 key,staleTime ↔ TTL,invalidate ↔ evict
- representation_shift:网络时序图(QuerySim/CorsSim)
- transfer_target:Caffeine、Redis、网关
- future_hook:乐观更新与离线冲突留给 Capstone 实战

**phase4 · 工程化**
- returning:缓存(内容哈希/CDN)、依赖治理(Maven 表亲)
- new:npm/semver、Vite、摇树、Vitest/RTL/MSW、Docker、Sentry
- added_complexity:交付链本身也是一条读写管线
- new_relation:摇树 ↔ 死代码消除;内容哈希 ↔ 缓存协议自动化
- representation_shift:源码视角 → 构建产物视角
- transfer_target:Jenkins/CI 流水线、nginx
- future_hook:compose 编排直接服务 S42 部署场

**phase5 · RN + Capstone**
- returning:四条全部回来(终极综合,总答辩考的就是这张表)
- new:JSI/Expo、导航、权限三态、OTA
- added_complexity:第四块大陆——原生世界与序列化边界
- new_relation:JSI ↔ JNI
- representation_shift:"两世界一通道"白纸图
- transfer_target:全栈统一场(Capstone 双端一致 + 409 拦截)
- future_hook:无(毕业 🎓)

## 假螺旋自检(每阶段末跑一遍,任一命中即回炉)

- [ ] 同一概念多次出现,但打卡增量写不出"多了什么"→ **重复,非螺旋**
- [ ] 后面只加术语,没有新的结构理解 → **词藻膨胀**
- [ ] 整阶段全是新概念,四条不变量一条都没回来 → **线性课程**
- [ ] 所谓回顾都堆在阶段末的总答辩 → **复习式课程**
- [ ] 概念回来时情境和表征与首次完全相同 → **情境复读**
- [ ] 只是题更难了,概念没有更深 → **难度爬坡≠概念升阶**

材料修订窗口同理:改动 MAP/实验卡时,先查本文件的遭遇史,不许把某次升阶悄悄降回重复。
