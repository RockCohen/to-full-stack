## 0. 世界观开场:UI = f(state)

后端的荣耀是"给定输入,计算输出"——纯函数。React 把这份荣耀带给了界面:**UI 是状态的纯函数投影**。你不写"先清空列表再逐行添加"的命令式代码(那是 jQuery 时代的手工 dirty-flag),你只声明"这个状态长什么样",React 负责把界面从旧状态搬运到新状态。

**读写世界观落点**:渲染是一次**只读事务**——读 state(不许写),产出界面的" SHOULD 快照"(vdom);真正的写(碰真实 DOM)由 React 统一提交,按 diff 最小化执行。c02 的"脏页最小回写"、c00 的 Copy-on-Write,在这里合体成一条流水线:**state 变 → 函数重跑 → 新 vdom → diff → 最小 DOM 更新**。

## 1. 组件与 JSX:UI 的函数化(第①②层)

### 1.1 先破一道墙:HTML/CSS/DOM 三件套(你还没有的基础)

写 React 前必须认识浏览器页面里的三个角色——**这是本讲义唯一的强制前置**:

- **DOM(文档对象模型)**:浏览器把 HTML 解析成一棵内存里的对象树——每 个标签是一个节点(`<div>`、`<span>`、文本都是)。它是"界面数据"本身,≈ 你的 ORM 实体树。**JS 操作界面 = 操作这棵树**。
- **HTML**:声明这棵树的原始标记,`<div id="a">文本</div>` ≈ 一行建树脚本。
- **CSS**:描述树上每个节点"长什么样"(颜色、布局),≈ XSL/皮肤系统,不参与树结构。

React 的全部工作可以一句话说清:**让 JS 函数直接产出这棵树的"描述稿",再由 React 对比真实 DOM 做最小更新**。

### 1.2 JSX:在 JS 里写"树的描述稿"

```tsx
function OrderRow({ id, total }: { id: string; total: number }) {
  return <tr><td>{id}</td><td>{total} 元</td></tr>;
}

function OrderTable({ orders }: { orders: Order[] }) {
  return (
    <table>
      {orders.map(o => <OrderRow key={o.id} id={o.id} total={o.total} />)}
    </table>
  );
}
```

JSX 不是 HTML,是语法糖:编译后就是 `createElement('tr', …)` 函数调用(c00 的蒸发规则对 JSX 同样生效——产物是纯 JS)。花括号 `{}` 里是**任意 JS 表达式**:`{total} 元` ≈ 字符串拼接,`{orders.map(…)}` ≈ "子节点是映射出来的数组"。**类比:JSX ≈ JSP/Thymeleaf 的函数版**——但你写的是类型安全的代码,不是模板字符串。

### 1.3 组件 = 接收 props 的函数

组件就是"接收 props、返回描述稿"的函数:`OrderTable({orders})` ≈ `render(orders)`。两条铁律:

1. **props 只读**(≈ 不可变入参):组件不许改 props——要改数据,找状态的拥有者(它会把新 props 重新发下来);
2. **渲染必须是纯函数**:同样的 props,必须渲染出同样的结果;渲染函数里不许有副作用(请求、改外部变量)——副作用有专门的容器 useEffect(S23)。

**类比失效的地方**:你后端的 Service 方法可以有副作用(发 MQ、写库),React 渲染函数**一次都不行**——渲染可能被 React 随时重放(StrictMode 下故意跑两遍),副作用会成倍发生。副作用与渲染的分离,是 React 的第一纪律。

## 2. 渲染与虚拟 DOM:脏页最小回写(第③层)

### 2.1 vdom:界面的"待写页"

setState 之后发生了什么?**你的组件函数重跑**,产出一棵新的 vdom 树(JS 对象描述的"界面应该长什么样")。React 拿新旧两棵 vdom 做对比(diff),只把差异应用到真实 DOM。

用你数据库的语言:**vdom 是 WAL 里的待写页,真实 DOM 是数据页,commit 是检查点**。直接操作 DOM ≈ 绕过缓存手写每一页(慢、易错);先写 vdom 再 diff ≈ 攒一批、算最小集、一次落盘。

### 2.2 diff 的规则(以及 key 的意义)

React 的 diff 有一条工程上的简化:**同层比较,不跨层移动**。同一位置:类型相同(都是 `OrderRow`)→ 更新 props 复用节点;类型不同 → 拆掉重建。列表场景靠 **key** 对齐身份——**key 就是主键**:没有 key,React 按位置配对,删除首行后"第二行的实例顶了第一行的位",行内状态全部串位(门诊 1 号);key 用业务 id(别用数组下标!)。

**对暗号:数据库为什么要求主键稳定?** 因为行身份是状态(外键、关联)的锚。列表 key 同理——**身份漂移 = 状态串位**,这是同一个原理在界面层的重演。

### 2.3 为什么要学手写 mini-React

因为 diff 与 Hooks 的"说明书"你背过一万次,但"为什么这样设计"只有亲手实现才会长出来。S18~S20 的禁写区只要求 ~200 行:minimal diff(同层、按位置)、函数组件、useState 槽位、useEffect。写完你会发现:**React 的复杂度不在原理,在工程化的边角**——原理 200 行,边角两万行。

## 3. Hooks:Fiber 上的固定槽位(第③层 · 你选题的落点)

### 3.1 状态逃逸的终局形态

阶段 1 你已经推演过两次:闭包让变量逃逸到堆(c04);订阅-通知让"数据的变化"活过函数(c06 手写的 store)。Hooks 是第三次,也是终局:**让"组件的状态"活过组件函数的每一次渲染**。

函数组件每次渲染都是从头执行——栈帧里的局部变量活不过一帧。那 useState 凭什么记得住上一次的值?因为状态根本不在栈帧里:<b>它记在组件在 Fiber 节点(组件在堆上的"户口本")的 Hook 槽位链表里</b>。useState 做三件事:第一次渲染,在链表上按顺序开一个新槽;此后每次渲染,按**同样的调用顺序**去链表上认领同一个槽;setState 则安排一次重渲染。

所以"Rules of Hooks"(不能写在 if/循环里)不是语法洁癖,是**调用约定**——槽位按顺序寻址,你在 if 里少调一个,后面全部槽位错位,等于寄存器分配表被扯歪。模拟器 c09 会把这个错位演成动画。

### 3.2 常用 Hooks 的"翻译表"

| Hook | 它管什么 | 你后端的老朋友 |
|---|---|---|
| useState | 组件的私有可变状态(写入口 setState 安排重渲染) | 实例字段 + 脏标记 |
| useEffect(fn, deps) | 渲染后的副作用:挂载后执行、deps 变化重跑、返回清理函数 | @PostConstruct + @PreDestroy + 缓存 key 三合一 |
| useContext | 跨层读"注入的环境" | Spring IoC 的依赖注入 |
| useMemo/useCallback | 手动缓存计算结果/函数引用 | @Cacheable(但 key 要自己写对) |

useEffect 的依赖数组就是**缓存 key**:数组里每个元素参与"要不要重跑"的比较;漏写一个依赖 = 缓存 key 不完整 = 读到旧值(stale closure,阶段 1 门诊的回声);不写 deps = 每次渲染都重跑 = 缓存击穿风暴(门诊 2 号)。

## 4. 状态管理与通信:单向数据流(第③层)

- **props 下行**:父把数据传给子(≈ 方法参数,只读);
- **事件上行**:子要改数据?父把"改数据的函数"作为 props 传下来,子调用它(≈ 回调接口);
- **状态提升**:两个组件要共享状态?提到它们最近的公共父级;
- **Context**:跨多层的"环境注入"(主题、当前用户)≈ IoC 容器:上层 provide,下层 use,不用层层透传(避免"prop 钻孔")。

**原则一句话:状态放在"需要它的组件的最近公共祖先",数据永远单向下行。** 双向绑定(界面直接改数据)是 React 明确不走的路——所有写都收敛到状态拥有者的 setState,和你后端"所有写走 Service,不直改表"是同一条纪律。

## 5. 对暗号(本阶段总表)

| Java/OS 世界 | React 世界 | 一句话 |
|---|---|---|
| 纯函数计算 | 渲染 = 纯函数 | 同输入必同输出,禁止副作用 |
| WAL 待写页 + 检查点 | vdom + diff 提交 | 先算后写,最小回写 |
| 主键稳定 | 列表 key | 身份漂移 = 状态串位 |
| 实例字段(堆上) | Hook 槽位(Fiber 上) | 状态逃逸,按序寻址 |
| @PostConstruct/@PreDestroy | useEffect + 清理函数 | 生命周期三合一 |
| 依赖驱动的缓存 | 依赖数组 | key 不全 = 读旧值 |
| IoC 注入 | Context | 跨层注入,免钻孔 |
| 所有写走 Service | 所有写走 setState | 收敛写入口 |
